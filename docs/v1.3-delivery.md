# 1.3 个人记忆交付候选

2026-10-08，源码版本 `1.3.0-rc.4`。本轮按 [当前路线](refactor-next-steps.md) 继续完成 v1.2 的实际使用链和 v1.3 五批核心功能。源码通过 `codex/animemo-next` 分支交接，候选尚未正式签发或发布 Release。旧项目数据兼容、主题插件、第三方市场、PWA 不在本轮范围。

## RC4 发布收尾

应用固定到提交 `8942721`，已构建新的 RC4 Linux amd64 镜像。真实 RC2 → RC4（19 → 21 迁移）、完整记忆库和上传徽章恢复、加密备份、升级失败回退、显式回滚、Worker/扩展及中断恢复已通过；具体摘要和证据见 [验收记录](verification.md)。原 RC2 包保持不变，新完整包的使用方式见 [本地交接](local-package-handoff.md)。

发行流程补入完整记忆恢复与可验证的旧版选择。云端打包时 GitHub 授权不可用，本机已接手源码、镜像及 Windows 升级验收，具体范围见 [验收记录](verification.md)。候选尚未远端签发或发布。当前首发范围为个人/小型自托管、Linux amd64、Compose、PostgreSQL 17；邮件/OAuth/R2 的真实服务验收未完成，保持默认关闭。

## RC4 功能阶段：系列主图、等级辨识与自动授予

后台支持上传 PNG/JPG 系列主图并实时预览；内置主图扩展为 8 种。同系列按等级使用青铜、白银、黄金、铂金、幻彩边框，并逐级加入月桂、冠饰和宝石。条件数量仍由管理员设置，默认门槛没有批量修改。图案只占徽章中心，上传后仍保留等级视觉。

发布、重新启用或修改统计门槛后自动评估已有账号，用户不必再次记录；纯文案或图案修改不重扫全站。复用 PostgreSQL 原队列，每轮最多 10 个账号，并修复规则发布和 Worker 并发时读取旧规则的漏算窗口。迁移 021 保留旧修订和历史图案；JSON/ZIP 跨实例恢复包含图案字节，陌生规则仍保持停用。说明见 [成就内容](achievement-content.md)，源码/浏览器/数据库证据见 [验收记录](verification.md)。没有新增生产依赖；功能阶段曾只交付源码，随后的镜像收尾见上节。

## RC3：为记录与回顾留下纪念

在五种 SVG 纪念章、六槽纪念架和后台图案预览基础上，新增 7 枚默认成就，共 6 个系列、12 枚成就。新增“已记录作品、有内容的收藏夹、选入记忆的年度册”三个统计条件，独立回忆增加两个等级；只记作品名或未知日期均可解锁，不要求补齐观看事实。图鉴加入系列筛选与条件说明，后台默认统计已记录作品。

迁移 020 保留旧规则和自定义等级，异步评估已有记录；补齐年度册保存和作品软删除/恢复触发。多 Worker 去重、冻结补算、撤回不重授与 JSON/ZIP 历史携带已验证。完整规则见 [成就内容](achievement-content.md)，证据见 [验收记录](verification.md)。本轮源码和开发服务已更新；原 RC2 镜像、ZIP、独立验收容器仍保留原版本，没有宣称已发布新镜像。

## RC2：围绕记录与回顾收敛

按用户明确定位，AniMemo 保存看过的番剧与相关经历，不承担追番排期、更新提醒或观看任务。本轮不提前扩张 1.4 平台能力，优先减少记录负担：

- 新建只展示作品名和选填感想；评分、状态、资料、颜色与分享设置按需展开。保存后在详情补 Bangumi 资料或封面，避免填写中跳转丢失正文。
- 新状态 `recorded` 表达看过但细节未记。仅作品名不会生成日期、逐集历史或完成统计；卡片以感想和已记录事实为主，不展示完成进度条。现有状态与数据不批量改写。
- 卡片「留点回忆」复用独立笔记，自动关联作品并填好可编辑标题，默认未知日期、私密。角色/集数查询等到用户展开关联工具才请求。
- 需要逐次记录时再从详情打开观看表单；新表单不预填今天、下一话或首刷。精确字段不记得时可以直接写回忆。
- 记忆库主导航保留札记、瞬间、收藏、年度与找回；角色、集数、图片管理和徽章收进「更多整理工具」，直接链接和已有能力继续可用。
- JSON/ZIP 带走新状态与独立回忆，迁移 019 扩展状态及保存的筛选条件。Bangumi 没有对应的模糊状态，写回预览明确提示，不能猜成已看完；其他作品按各自状态处理。

新增功能按“记录 → 留下回忆 → 找回 → 带走”的实际使用价值排序。VM 和长时负载仍可选。验收证据见 [开发验收记录](verification.md)。

## 数据和权限边界

- Anime、Character、Episode 使用本地 UUID。角色/集数归并只记重定向，不重写原笔记引用；拆分可恢复原身份。目录变化和进度快照都不会制造逐话观看事实。
- 独立笔记编辑带版本号。观看记录撤回、条目移出不会级联删除笔记正文。新的长期数据由 `journal` 核心事务持有，扩展没有 SQL 或 UI DOM 权限。
- 私人图片当前保存在 PostgreSQL，原件与 SHA-256 不可变，缩略图是可重建派生物；与封面/R2 管线分开。未关联上传预留有效 24 小时，Worker 每分钟分批回收。曾关联的原件由用户主动删除，删除会清空原图和缩略图，保留墓碑引用。
- 年度统计以保存的日历年份为口径，未知年份不计入；话数为观看记录区间之和，重看也在其中，不声称唯一看过的集数。时区、统计口径、截止点和 `memory-year/v1` 算法标识保存在每次修订。选材既可以含当年的精确记忆，也可以保留不确定日期。
- 分享凭证只存哈希，可设置 1–90 天、轮换、撤销，响应 `private, no-store` 且不索引。公开年度册只展示装订时和当前均允许分享的来源；后来公开笔记不会暴露旧的私人冻结正文。转私密、账号停用/关闭分享、来源移出、原图删除会作用于后续读取。
- 成就规则支持 8 种内置条件：已记录作品、有观看记录的作品、观看记录、已看完作品、记录话数、独立记忆、有内容的收藏夹和选入记忆的年度册。解锁与授予分开保存；撤回不会抹去解锁历史，也不会被自动任务重新授予。规则修改不改写既有解锁引用的修订；补算固定规则版本和账号名单，逐批检查管理员资格。
- 统一检索与记忆串直接读取核心表，使用 PostgreSQL 字符串模糊匹配，按账号隔离。没有 Redis、额外搜索服务或第二份可写记忆库。

## TXT 与完整备份

随附 TXT 扩展版本递增为 **1.1.1**。声明宿主 API 2（来源字段），旧宿主在安装前拒绝；1.3 宿主同时接受原 API 1。同版本包字节不可改写；这避免了 1.1 宿主升级时与旧随附包发生不可变身份冲突。解析结果仍进入核心持久导入任务，确认前不写手账。

普通导入可以选择作品和其中的观看记录，或明确指定已有作品及其版本后追加。追加不覆盖原评分、正文、资料或封面；日期、精度、区间、刷次、笔记均相同才跳过。相同观看范围但正文不同的 TXT 行会保留，不再丢掉后一条记忆。预览后手账变动会使整个提交失败，需要重新核对；不会提交一半。

`animemo.journal/v3` 在 v2 基础上携带独立记忆、角色/集数、关系、进度快照、私人图片原件、收藏、年度修订和成就历史。ZIP 另外携带封面原件。无新增记忆库数据时仍可以输出本项目 v2；这不是旧项目兼容层。

完整包需恢复到空手账：重新生成资源身份并重映射内部引用，保留有效时间精度、修订时间、可见性、冻结内容与顺序。不会导出密码、分享凭证或其他用户的管理者身份。导入的成就定义只用于个人历史，不激活目标站点的规则；完全匹配的既有规则可复用，否则保留为停用的历史定义。个人包不能让普通用户建立全站自动授予规则。

实例快照另含账号、密钥、完整任务、扩展包和所有数据库数据。恢复为新实例时撤销会话和记忆分享凭证、暂停正在运行的成就补算、关闭外部授权及扩展，供管理员审阅。正常更新保留原数据库与更新前快照，可独立回滚。

## 范围与容量

已执行环境为当前 Linux amd64 Docker/Compose、PostgreSQL 17；开发机是托管 Debian Linux，并非新装 Windows 或所有 Linux 发行版。先支持个人及小型自托管使用，不作大站并发或硬件性能承诺。

| 硬限制 | 当前值 |
| --- | --- |
| 独立笔记 / 单篇正文 | 10,000 篇 / 40,000 字 |
| 角色 / 集数 / 单次建集 | 5,000 / 50,000 / 2,000 |
| 单次进度快照 | 最多 2,000 个明确的集数与版本 |
| 私人原件 | 每张 2 MiB，账号 100 MiB，最多 10,000 个未删除原件或预留 |
| 收藏夹 / 单夹项目 | 500 / 500 |
| 年度册 / 单册修订 / 单版选材 | 300 / 100 / 200 |
| 个人文件导入 | JSON 144 MiB；ZIP 256 MiB；CSV 2 MiB |
| 当前条目 / 观看记录导出 | 5,000 / 20,000；超限明确报错，不截断 |

这些是防止无界处理的限制，不等于逐项测试了最大容量。已验证包含 1,200 集目录的分页、原子重复拒绝及定向并发；更大个人文件或超限历史使用完整实例快照。VM 和约 25 分钟负载仍为按需人工检查。

## 验证与后续

实际结果、镜像及证据见 [验收记录](verification.md)。新增回归入口：

```bash
npm run check:web
# 在运行中的合成验收实例上检查记录主链；使用真实 API，会创建测试账号
REVIEW_ORIGIN=http://127.0.0.1:18082 node tooling/recording-browser.mjs
npm run check:api
npm run test:api -- -run 'TestMemory|TestPrivateMemoryMedia|TestSelectedImport|TestTextRecordsAndAmbiguity'
npm run test:api -- -race -run 'TestMemory|TestPrivateMemoryMedia|TestSelectedImport|TestTextRecordsAndAmbiguity'
ANIMEMO_PREVIOUS_IMAGE=旧镜像 ANIMEMO_CANDIDATE_IMAGE=候选镜像 node tooling/memory-instance-smoke.mjs
```

浏览器脚本使用 `.local/tools/browser` 中的 Playwright / axe-core 与系统 Chromium；`ANIMEMO_BROWSER` 可指定 Chrome 可执行文件。需要实例开放注册；仅在开发或验收环境运行，不对正式站点运行。

最后一条只操作并清理自己创建的 `probe-*` 实例。收尾版探针要求旧镜像具备 RC2 或更新的记录 API，先建立完整记忆数据再验证升级、真实 Worker、私人原件、上传徽章和跨实例完整恢复。它是按数据模型变动及发行选择的检查，不加入每次编辑的默认门禁。

邮件真实收件、Bangumi OAuth、R2 正式凭据、域名/TLS、公网验收及远端签发仍按 [本地交接](local-network-handoff.md) 独立完成。没有把受控接口测试写成正式第三方服务支持。主题插件、语义插槽、个人持久授权、第三方运行时属于 v1.4；本轮没有把当前 CSS token 当作公开主题 SDK。
