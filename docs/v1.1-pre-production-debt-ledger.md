# AniMemo v1.1 Pre-Production Debt Ledger

Status: ACTIVE UNTIL v1.1.0 STABLE

This ledger records compatibility debt decisions made while AniMemo v1.1 is
still pre-production. Accepted debt requires an ID, rationale, owner, and a
future resolution rule. No debt is currently accepted.

## PCDC-001 — Canonical filesystem clean break

**CURRENT CONTRACT**

The original Phase 1 filesystem and installer contracts allowed custom roots
and a read-only v1.0/1Panel compatibility profile. The original Phase 2 Backup,
Migration, Doctor, and Compatibility contracts carried that profile into
source discovery, protected-config capture, and migration planning.

**TECHNICAL DEBT**

Implementing those clauses would require a second filesystem discovery path,
legacy configuration readers, profile-dependent backup capture, a legacy
migration source reader, and a future cutover state machine alongside the
canonical v1.1 path.

**WHY COMPATIBILITY IS NOT REQUIRED**

AniMemo has not entered production and v1.1.0 is not Stable. The historical
development layouts have no user or production compatibility obligation.
Long-term user data semantics remain protected independently from support for
an unpublished host layout.

**LONG-TERM COST**

Keeping the old clauses would permanently multiply destructive-operation test
matrices and make every Installer, Backup, Restore, Migration, Doctor, and
Updater path reason about two authorities for roots and protected config.

**PROPOSED CLEAN CONTRACT**

v1.1 supports one deployment profile, `v1.1-standard`, and the five canonical
roots. Runtime tools do not scan, read, adopt, convert, or fall back to
pre-v1.1/1Panel paths or configuration. Unexpected existing state is Foreign
or Partial/Ambiguous and fails closed without overwrite or deletion.

**AFFECTED DOCS**

- `deployment-boundary-v1.md`
- `filesystem-layout-v1.md`
- `installer-contract-v1.md`
- `backup-contract-v1.md`
- `migration-bundle-v1.md`
- `doctor-basic-contract-v1.md`
- `compatibility-matrix-v1.md`

**AFFECTED TESTS**

- `scripts/tests/test_recovery_migration_contracts.py`
- existing canonical locator/Doctor tests continue to prove that legacy roots
  and unknown profiles fail closed without discovery fallback

**DATA / MEMORY INTEGRITY IMPACT**

The correction strengthens integrity. It removes ambiguous path adoption and
does not change database, Resource Identity, instance identity, secret,
Release Identity, or MI-1..MI-5 semantics. Existing unexpected data is never
deleted or overwritten; it is rejected for explicit operator disposition.

Decision: RE-FROZEN FOR v1.1 before Restore/Migration runtime implementation.

## PCDC-002 — Phase 3C Installer prerequisite clean corrections

Phase 3C found five unpublished deployment prerequisites whose current forms
would create permanent dual authority or unverifiable execution: incomplete
Release materials, noncanonical Updater discovery/adoption, missing managed
configuration, unproven platform support, and missing Fresh-install recovery
evidence.

The complete CURRENT CONTRACT / CURRENT PROBLEM / LONG-TERM DEBT / OLD BEHAVIOR
/ CLEAN CONTRACT and Data / Memory / Release / Migration / Rollback impact
record is [Phase 3C Pre-Production Contract Corrections](phase3c-pre-production-contract-corrections.md).

Decision: RE-FROZEN AND IMPLEMENTED FOR v1.1. Schema-v1 Release assets,
panel/cwd/env discovery, app-tree environment authority, mutable dependency
tags, invented platform floors, arbitrary operation metadata, legacy readers,
and compatibility shims are not accepted debt and receive no Adapter. Final
Release use remains gated by candidate-bound GitHub-hosted platform evidence;
that evidence requirement is an active gate, not accepted compatibility debt.
