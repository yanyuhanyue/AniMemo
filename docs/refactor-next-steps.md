## 产品定位与取舍标准

AniMemo 用于记录看过的番剧与相关经历，不承担追番排期、更新提醒、播放服务或观看任务。衡量交付的标准是：**简单的记录足够轻，丰富的回忆装得下，多年以后找得到、带得走。**

- **核心入口：** 作品名即可保存。评分、完成情况、观看时间、具体集数和重看次数只在用户明确提供时记录；“高中时看过”“记不清日期”均是有效内容。录入时间与观看时间分开，不用今天、下一话或作品总话数填补未知经历。
- **自然延伸：** 感想、私人图片、标签、收藏和年度回顾，帮助保留与找回经历。先允许自由文字，再按需添加结构化关联。
- **可选整理：** 角色库、集数目录、范围快照与成就保留，但不成为普通记录的前置步骤；通过次级入口按需展开。
- **扩展定位：** 插件服务于导入、整理、展示和检索。停用、缺失或撤销扩展后，核心记录仍然可读、可导出。授权与隔离保护现有消费者，不以全面平台化作为记录功能的前置。
- **保护已有内容：** 不批量改写用户现有状态、日期和资料。既有 planned/watching 等状态保留真实含义以支持已有记录和显式外部同步；新手动记录与资料搜索默认 recorded（看过，细节未记），不引导建立想看队列。

版本号和功能数不是产品体验完成度。每轮优先验证实际链路：记下一部旧番 → 留一句记忆 → 找回 → 导出/恢复；遇到真实阻力就修复，不新增固定天数的试用或验收门禁。

## 1. 当前起点与约束

已具备并有相应验收记录：个人手账、观看与重看记录、日期精度、记忆修订、导入导出、公开分享、专栏、账号安全、管理后台、独立 Worker、事务 Outbox、Docker 实例安装、备份恢复、更新回滚和受限 WASI 文件转换扩展。后台已完成独立布局和桌面/手机真实浏览器验收。

Bangumi 公开资料曾在本地通过真实服务验证；邮件、OAuth、R2 已实现且通过受控测试，正式凭据联调仍未完成。官方 TXT 扩展已有随附身份和独立进程边界；个人持久授权、第三方市场和 Bridge 尚未完成。详细事实以 [验收记录](verification.md)、[功能清单](feature-parity.md)、[扩展边界](plugins.md) 为准。

原项目功能覆盖仍按既有 62 项统计，目前记录为 52/62；这不是工作量、发布就绪度或新路线完成率。保留缺口，不通过重写路线改变计分。按全新项目开发，不兼容旧项目的数据、API、插件 ABI 或安装目录；本项目后续产生的数据和已发布协议仍需明确的升级、导出与恢复策略。

长期方向是可自托管的个人番剧记录与回忆档案：围绕已经发生的观看经历，先降低记录和找回的成本，再扩展记忆表达与插件能力。产品功能和必要的可靠性工作交替交付，不先建一套庞大的发布平台。

| 范围 | 当前基线与安排 |

| Windows | 保留 PowerShell、工具路径识别和本地启动入口，用于开发、用户验收、外部服务联调；推荐 WSL2 或 Docker Desktop Linux 容器 |

| 云端网络与凭据缺口 | 在 [本地交接](local-network-handoff.md) 记录服务、所需配置、执行步骤和未验证范围，继续推进无依赖的工作 |

保留 `server/`、`web/`、`contracts/`、`tooling/`、`deploy/` 的现有分工。Go 模块化单体和独立 Go Worker 已满足当前需要；不引入 Python 过渡层、Redis、微服务或通用消息平台。`journal` 拥有核心事务，扩展通过版本化数据协议调用业务入口，运维代码留在 tooling/deploy。UI 通过本地基础组件与设计 token 复用，不直接耦合数据库或插件运行时。

Windows → VMware → SSH → Linux 的中转链、VMX/MAC/IP 编排、整套 VM Campaign Controller、Windows 专属 Secret Broker 不进入新项目默认实现。轻量 Windows 脚本继续保留；开发平台选择不等于承诺该平台的生产支持。

## 3. 验证规则与时间成本

### 日常按改动选择检查

| 改动 | 必要的开发验证 | 按需增加 |
| --- | --- | --- |
| 路线、普通说明文档 | 差异、链接和实际命令一致性 | 可执行示例变动时验证对应命令 |
| 纯 UI / 交互 | `npm run check:web`；查看受影响页面和关键交互 | 改动较广时补桌面/手机浏览器流程 |
| Go 业务 / API | `npm run check:api`；受影响单元与真实 PostgreSQL 集成 | 并发、事务、任务认领变动补 race；合同变动同时检查 Web |
| 数据迁移 / 导入 / 备份 | 真实 PostgreSQL 的完整性、权限、失败恢复测试 | `npm run test:instance` 验证相关升级、恢复路径 |
| 部署 / Worker / 扩展执行 | 受影响的真实容器、进程和消费者流程 | 按范围选 `test:containers`、`test:stage3` 或 `test:plugin-instance`，避免重复覆盖 |
| 依赖、构建、CI 或影响范围不确定 | 扩大到相关前后端和构建验证 | 交付候选时完成一次适用的完整回归 |

`npm run verify` 保留为主动选择的全量入口，不是每次修改或每次本地提交的固定前置。相同源码与输入已通过的检查不连续重复执行；出现新改动、失败或具体疑点时再补对应验证。缓存用于依赖和编译，数据库验收不能拿旧结果冒充新执行。

本地先发现问题，GitHub CI 独立验证提交。当前 CI 已有 Web/API 范围选择和 `required` 汇总；它并未实现上述所有细分选择，也不是完整发行流水线。不伪造远程通过状态。默认验证完成后继续开发，不等待可选专项。

### VM 与 25 分钟负载测试：明确可选

- VM 验收与固定约 25 分钟的持续负载测试均为**手动选择的专项**，不作为日常开发、PR 合并或版本发布的默认必经条件；未执行不阻塞后续开发，不得自动升级为强制门禁。
- 不接入 `npm run dev`、`check`、`verify`、默认 PR CI、`required` 汇总或发布的自动前置依赖。以后新增专项入口也保持独立，不建立“跳过专项就整条流程失败”的关联。
- VM 可用于排查干净宿主安装、权限、系统依赖或新增平台问题；容器检查通过只证明已测环境，不自动宣称已完成空白 OS 安装验收。
- 长时负载可用于已发现的泄漏、队列积压、容量或性能疑点；运行前写明要回答的问题、数据规模和结束条件，不为凑满 25 分钟固定等待。
- 没有具体问题时不主动安排多轮 VM 或长时压测；也不要求先收集 10/20 轮完整流程才能做明确有益的优化。
- 主动开展专项时可后台运行，并继续无关开发。结果记录为通过、失败、未执行或环境受限；未执行绝不能写成通过。发现真实数据损坏或权限问题，修复并定向复验相关功能，不以“专项可选”为由忽略缺陷。

不另建通用压测、VM 调度或证据签名平台来执行上述规则。当前仓库没有 VM/25 分钟压测命令，本轮没有新增这些依赖。

### 合并重复成本

- 优先使用现成工具；只为已有消费者定义边界，不预建全量 SDK、合同注册中心或无消费者事件框架。
- 发行候选只构建一次，测试、上传和晋级消费同一摘要的产物。文档更新不触发应用重建；产物或其输入变化后重新验证受影响部分。
- 一份简明回执记录提交/工作区差异、镜像摘要、测试范围、工具/环境、结果和未验证项；不为每次文件复制建立独立回执系统。正式发行必须绑定确定的源码提交。
- 已有公开发行物继续使用摘要和成熟的来源验证机制；校验和不能替代发布者身份验证。
- 开发步骤完成即返回。记录明显慢项后针对优化，不按旧路线强行等待、不预先承诺节省比例。既有耗时仅作本环境观察值。

### v1.1：部署与交付收口

已有能力继续复用：独立 Compose project、默认回环监听、初始化、数据库/媒体备份、恢复到新实例、候选升级、失败回退、Worker 和扩展预检。

1.1 的实现和验证状态见 [交付记录](v1.1-delivery.md)：诊断/配置、快照计划、加密转移及发行入口已实现；正式远端签发/下载验证仍待具备条件后完成。以下保持该版本的验收目标：

1. **诊断与配置。** 为现有实例 CLI 增加明确的环境预检查和 `doctor` 入口，覆盖 Docker/Compose、空间、端口、目录权限、配置、数据库、Web/Worker 状态；提供可预览的监听地址/Public Origin 修改、原子保存、健康失败恢复。只操作本实例，不接管 DNS/TLS。
2. **备份与迁移。** 补全版本/源码/迁移/扩展/媒体清单，恢复前展示兼容性和将改变的状态；保护随备份转移的实例及外部服务密钥，采用成熟加密方案。复用现有恢复到新实例的路径；补足相关操作中断恢复，避免失败后需要猜测当前状态。
3. **最小发行。** 统一产品版本元数据，源码提交绑定一个候选镜像及清单；复用成熟签名或来源证明工具验证发布者和摘要。安装入口消费已验证产物，保留本地镜像与离线载入方式；不自建信任平台、不要求多镜像源同时就绪。
4. **交付验收。** 在声明支持的 Linux/Docker 环境完成一次适用的功能回归和实例安装、更新失败、备份、新实例恢复验证；发布后核对真实下载产物及来源，并做启动冒烟。同一产物晋级不重建。VM 和 25 分钟负载仍按可选专项规则执行。

完成标准：按公开文档可重复安装/配置/诊断；关键数据、媒体、密钥和扩展状态能按说明恢复；更新失败有明确恢复路径；运行版本可对应源码与验收产物。源码中仍为计划的命令必须先实现再写成可执行用法。

1.1 不要求：新 Go Host Agent 常驻服务、Secret Broker、VM 控制器、R2 发行镜像源、组织迁移、仓库目录大搬迁、插件市场或角色记忆。图床 R2 与发行镜像源是两件事；图床已有功能继续维护和联调。

### v1.2：日常体验与真实消费者

- **同一设计体系、三种展示模式。** 手账、详情、角色、时间线、收藏、年度记忆采用 Memory Editorial：作品与时间优先、相册式留白、适合长期阅读。Universe、专题海报和年度开场可用 Cinematic；后台、设置、备份恢复和插件管理采用 Calm Utility。保留二次元气质，避免所有页面都变成装饰卡片或高动效展示。Universe 先交付轻量作品展陈，键盘、手机和减少动效模式均可使用；不先建设 3D 引擎。
- **UI 平台。** 继续 Tailwind 4 + Base UI + 本地基础组件，统一语义 token、表单、空态、焦点/错误、加载和触控尺寸。逐步补齐基础/语义/组件/动效 token；不把当前少量 CSS 变量当作稳定主题 SDK。封面取色仅影响局部装饰，正文、危险操作和焦点不随图变色，并有明暗/高对比回退。主题模式逐步验收。CSS 优先，复杂动效有需求再引入 Motion/GSAP，避免重复管理同一属性。
- **手机与可访问性。** 底部导航、窄屏操作面板/Sheet、Dialog 安全区与滚动；覆盖键盘、焦点恢复、200% 缩放、减少动效、触控目标。自动扫描配合真实交互，不把扫描零问题等同于完整无障碍认证。
- **首页身份与隐私。** 明确私人首页、站点/公开主人页、演示和分享入口；站点主人由配置指定，不能回退到首个管理员。匿名只读 PUBLIC，不因登录失败改读公开或演示数据；UNLISTED 只经有效分享凭证访问。按身份隔离缓存、注销/切号中止旧请求；私人响应禁止共享缓存。保持此项目的新路由，不为旧 URL 加兼容层。
- 完善资料源搜索、封面失败/重试/手动上传及字段覆盖规则；用户评分、观看和笔记始终由本地核心持有。
- TXT 导入支持逐项选择、来源行追溯、明确匹配已有作品后追加记忆、重复/冲突说明；确认前不写核心数据。官方扩展继续通过核心导入事务提交。
- 完善扩展版本、权限与错误提示。继续覆盖坏包隔离、停用、卸载和备份恢复；此版不开放任意第三方 UI 脚本或后台写权限。
- 邮件实际收件、OAuth 授权/收藏、R2 真读写按凭据可用性独立验收；受阻项保留说明和默认关闭入口，不阻塞其他功能的开发。

完成标准：从添加番剧、记录/更正观看、导入核对到备份/分享形成可操作链路；导入追加不丢记忆、不静默合并冲突。未真实验收的外部服务不宣称已支持。

### v1.3：个人记忆与生产交付

这些是原产品目标的保留项，不再降为无排期的“可选想法”。子里程碑表示依赖顺序，不新增多套发布门禁；可分别交付 patch/minor，实际版本在交付时确定。

1. **记忆与身份基础。** 按 [Memory Core 合同](memory-domain.md) 实现独立 MemoryNote；Anchor 是其引用定位信息，可含集数、时间点、引用或场景，不独立拥有权限/时间线。支持作品/观看上下文、可见性、剧透与重点标记、附件引用。失效引用不能删除正文。沿用本地身份、日期精度和有效修订；时间线/MemoryThread 是可重建投影。提供基础笔记检索和可携带导出。
2. **长篇与角色。** Franchise 用关系表表达季、篇章、特别篇；Episode 使用本地身份与多资料源映射。区分主线/全部/自定义观看范围、必看/可选/排除和精确/近似/追平快照；资料更新不能生成观看事实。批量操作固定目标集合，长列表服务端分页。角色支持别名、作品关系、收藏、笔记、活动与记忆串；合并保留历史引用与重定向，误合并可人工拆分修复。初期不做好感数值系统。
3. **私人媒体与记忆瞬间。** PrivateMedia 持有原件、哈希和归属；私有读取授权、上传校验/限额、缩略图、垃圾回收和备份覆盖同步交付。MemoryMoment 支持同组 1–8 张截图及作品/角色/集数关联，提供图库与检索。上传采用预留→写入→验证→提交，避免把数据库事务假定为可回滚外部文件。原件删除后相关公开/年度投影不得继续泄漏媒体。
4. **组织与找回。** Anime/Character 收藏、Collection、标签和统一检索，覆盖笔记、年份、活动与状态。先用 PostgreSQL 全文/模糊检索；有真实瓶颈才增加独立搜索服务。MemoryThread/Gallery 与筛选共享核心事实，不能形成第二份记忆真相。
5. **年度记忆与成就。** 年度记忆及修订冻结选材、顺序、文案、统计口径、时区、截止点与算法版本；分享不扩大来源内容权限，UNLISTED 凭证可过期/撤销/轮换且不索引。成就保留系列/等级、徽章/进度、不可变解锁记录、受控规则、自动与管理员授予/撤销、补算预览及可暂停/续跑的幂等批次、通知/中心、最多 6 项展示和减少动效模式。授权与审计随功能交付；不加 XP、排行榜、赛季或插件自定义解锁规则。

每批长期数据模型都同步扩展导出、备份和往返验证，核对关系、日期精度、可见性、附件及合并重定向，不能仅比较条数。资料源消失不影响本地记忆；未知或不支持的数据不能被静默丢弃。

首次生产交付单独声明实际完成的子里程碑、平台与容量范围；核对权限、分享撤回、敏感信息、后台恢复和外部服务。在实际 Linux 部署环境完成小范围真实使用及恢复演练，修复阻断性安全/数据问题。余下产品目标仍保持“计划中”，不借首发验收改为“已完成”。不预设 25 分钟压测、三套 VM 或固定时长等待。

完成标准：用户的长期内容属于 Core，核心记忆可核对、可检索、可完整带走；承诺的平台与外部能力有真实证据。不宣称支持未经验证的环境、容量或第三方集成。其他功能照常开发，受阻能力可以明确移出本次生产范围。

### v1.4：主题定制、插件授权与最小 Bridge

按用户确认的顺序，先把可安装的主题做成真实消费者，再推进全站与桥接。`1.4.0-alpha.3` 已实现下面第 1、2 批；这不代表完整 v1.4 已完成。此前 alpha.2 的 token 主题继续兼容。实施边界与作者契约见 [札记主题](themes.md)。

1. **明确作用范围与协议边界（已实现首版）。** 当前仅开放私人札记；站点、个人和公开分享的后续优先级及安全界面边界写入契约。转换消息、主题描述和包清单分开，TXT 不依赖主题类型；保留既有不可变包身份及版本管理。
2. **以札记验证真实模板（已实现）。** 通用 HTML/CSS 模板与随包图片/字体；默认纸页保留。另一套官方「星笺展架」使用不同列表/阅读结构，并验证改名后的独立主题包能直接安装生效，无需核心针对主题名称分支。预览、个人选择、手机、停用回退与备份恢复随功能验证。
3. **逐页开放全站主题（下一批）。** 先私人手账与作品详情，再导航/站点首页、公开分享和年度册；每次从实际页面提炼模板槽。站点默认、个人选择与分享发布者的主题分开；公开模板只接收公开投影。登录、安全、后台及危险确认保持核心控制。先做出第二套实际版式再判断是否需增加契约，不预建页面搭建器。
4. **插件展示与个人授权。** 以一个实际插件需求开放一个语义插槽，区分发布者、包、安装和调用用户；权限显式授予、可撤销，在途结果提交前检查。依需要再扩展 `anime.detail.sidebar`、`journal.toolbar` 等插槽，不允许依赖宿主 DOM、数据库或框架对象。主题负责布局、插件提供受控内容，保持可独立停用。
5. **最小 AstrBot Bridge。** 从一个经用户授权的只读查询和一个真实事件消费者开始，复用 Outbox/去重。完成连通与撤权验证后再扩展动作，不先建设通用自动化平台。

每批独立验收并继续推进，UI、备份与实例升级不能因为主题建设停滞。官方包继续绑定核心发行身份，官方不扩大权限；通过现有版本启用/回退流程验证独立升级。插件目录/市场、通用 SDK、任意前端脚本和后台选择核心版本留待真实分发需求，不作为上述功能的前置。

开放不可信第三方市场之前再补发布者认证、隔离与审核；新增网络、持久状态或后台任务时同步交付相应授权、撤销及导出恢复。当前完成标准是实际消费者可安装、升级、停用、回退，撤销或缺包不影响核心内容读取与导出；不靠增加抽象层或固定耗时验证宣称完成。

### v1.5：维护体验与分发

完善备份计划、失败提示、存储占用、清理预览和保留策略；清理不能误删当前实例、可回滚镜像或仍有引用的数据。管理 UI 逐步提供备份历史/验证、恢复预览与确认、当前/目标版本、兼容检查、更新健康及回滚，复用 CLI 的业务能力，不复制第二套运维逻辑。新增常驻维护服务需有实际必要性。

- Doctor/诊断覆盖实例及 Site、邮件、Bangumi、Turnstile、媒体/R2、插件、备份/更新、健康、安全、审计与容量；未配置服务显示真实禁用/未验证状态。补充跨 Web/Worker/扩展的故障关联、指标/告警与按需 OpenTelemetry 导出，不强制自托管用户安装完整监控集群。
- 完善插件状态恢复：缺包保留数据且默认停用，升级/状态迁移失败可恢复，兼容声明可检查；不假装卸载插件等于删除用户数据。外部调用只在可重试、幂等的边界做有限重试。
- 封面/媒体继续补齐取回、验证、解码、尺寸与元信息处理、编码/哈希去重、提交和可追踪清理；不删除无法证明属于本实例的远端对象。网站封面与私人记忆附件分别管理权限。
- 插件目录/市场、安装门户、跨平台发行、离线完整安装包和发行镜像源按实际分发需求推进；不绑定旧域名、旧部署拓扑或特定发行镜像源。

### v1.6+：渐进式长期体验

- **再发现与记忆引擎。** 那年今日、重看建议、角色/作品/记忆推荐、人生阶段与偏好变化；记忆图谱是已有事实的投影，不扩张为百科平台。
- **AI 辅助。** 年度叙事遵循事实→用户选材→生成文案，标记来源与 AI 内容、可编辑；自然语言检索和问答能回到原始记忆，不凭空补写事实。凭据、隐私和选择发送哪些内容由用户控制。
- **PWA 分阶段。** 响应式→可安装→离线壳→明确范围的只读缓存→经授权的通知；切号/注销清除私人缓存，离线失败不冒充已保存。离线写入在冲突处理模型成熟后再做；Capacitor/原生端按真实需求决定。不能因为首版不做离线 CRUD 就从路线删除 PWA。

声优/制作人员记忆、角色关系图、集数百科、独立语录/场景库、高级好感度、社交关注/私信、完整原生端和复杂离线协作继续属于原方案的远期候选。它们不计入近期版本完成标准，也不与上面已保留的主要产品目标混淆。

v2.0 只用于确有必要的重大协议/数据边界变化，不作为收纳所有未完成想法的固定大版本。新功能进入执行前只回答：服务哪个用户问题、依赖什么、如何验收、增加多少长期维护面。

## 5. 接下来直接执行的顺序

1. 按新定位验收 `1.3.0-rc.4`：只填作品名、写模糊时间的回忆、稍后找回与完整带走，优先修复填写负担、数据与权限问题；入口和边界见 [1.3 交付](v1.3-delivery.md)。
2. 保留本轮 PostgreSQL、定向 race、容器升级/恢复及真实浏览器证据。按改动补验证，不反复重跑同一套已通过检查。
3. 在具备网络与凭据的环境按 [本地交接](local-network-handoff.md) 完成正式邮件/OAuth/R2 联调；独立记录结果，不混入已通过的核心功能。
4. RC4 已完成本地源码提交、镜像构建、真实升级与完整恢复收尾，详见 [验收记录](verification.md)。在可用的 GitHub 环境交接该源码，按 [发行说明](release.md) 签发并验证真实发行物；当前开发候选和验收站不冒充正式发布。
5. v1.4 第一批以札记主题作为真实消费者，已实现受限主题包。下一批按实际展示需求开放一个插槽，随后实现用户授权的 AstrBot 只读查询与一个事件消费者；市场和通用 SDK 保持后续排期。

当前源码版本为 `1.4.0-alpha.2`，只表示 v1.4 第一批开发交付，不表示完整 1.4 或正式发布。后续每次交付继续记录实现内容、实际验证、未验证项和阻塞原因；网络问题只阻塞依赖它的功能。
