# 原版能力补齐与架构推进顺序

对照基线为原项目 `94f64e7`，具体功能分母仍为 `feature-parity.json` 的 62 项。本文区分“真实已实现”“接下来可做”“需要本地外部服务验证”，不以建立接口或文档替代功能验收。

## 本阶段新增

- 版本化 JSON 插件 SDK、受限 WASI 文件转换、不可变本地包、管理员审阅安装 / 启停 / 历史版本切换与审计。
- 首个实际消费者：TXT 观看记录导入，保留日期、话数、刷次和笔记。它调用标准导入预览和确认流程，不直接操作数据库。
- 通用导入预览新增观看记录明细，最多显示 100 条，帮助用户确认解析结果。
- 插件支持范围 / 完整性纳入候选镜像的迁移前检查，包及启用状态随实例备份和回滚。

## 仍值得加入的原版功能

| 顺序 | 原版能力 | 当前差距与下一步 | 可否云端验证 |
| --- | --- | --- | --- |
| 1 | 完整观看记录 TXT 导入器 | 当前只做明确 UTF-8 日期和话数。下一步是逐项选择、排除、来源行追溯；随后设计“已有番剧追加事件”的幂等合并入口，不能绕过 journal 事务去直接写 SQL。多文件 / 编码探测按实际样例补齐 | 可以，真实 TXT 样例和 PostgreSQL 即可；Bangumi 匹配另列 |
| 2 | 插件个人安装管理 | 当前是管理员启用、用户主动选择文件。下一步补个人启用列表和授权展示；后台权限、账号绑定和撤销规则必须先明确 | 可以 |
| 3 | 插件市场、作者投稿与审核 | 当前只有本地包审阅，不存在在线目录、作者认证、签名 / 撤销、投稿队列。先做本地开发预览与受控审核，再连接发布源；摘要不可替代来源认证 | 本地状态与权限可验证；真实发布源另行验证 |
| 4 | Bridge 配对、动作与事件 | 未实现。先选一个只读动作，设计连接身份与能力授权；写动作使用业务入口、幂等 ID 和明确的重试策略，事件在提交后投递。旧版 PENDING 永久悬挂问题不能只靠增加超时重试解决 | 本地 Bridge 客户端 / HTTP 服务可验证，无需等待 GitHub CI |
| 5 | Bangumi 搜索、详情、条目标识和刷新 | 未实现 provider。先固定上游地址与响应 DTO，再做字段选择 / 冲突提示；不可覆盖用户笔记、评分和进度 | 真实接口受当前网络限制，本地接手说明已记录 |
| 6 | 外部账号授权、收藏预览和双向同步 | 未实现。授权、只读预览、确认导入、双向写回依次推进；任务恢复须区分安全重放与执行结果未知 | 真实 OAuth / 收藏联调需本地凭据和网络 |
| 7 | 邮箱验证与密码找回 | 未实现。需要单次令牌、统一响应、节流及持久发送任务，最后验收真实收件箱 | 邮件送达需本地服务配置 |
| 8 | R2 存储后端与迁移 | 默认 PostgreSQL 图片已可用。外部写入需要短事务预留 → 锁外上传 → 短事务确认，以及失败对账、旧图清理、迁移清单和外部对象回滚边界 | 协议错误处理可云端测；真实 R2 验收需本地 |

## 后续重构的约束

1. 不为未知扩展点先造通用事件总线、Repository 或权限框架。每加一种能力，用一个实际消费者和故障测试证明边界。
2. SDK 只交付可序列化合同，不泄漏数据库查询对象、事务、认证对象、宿主路径或 React 内部组件。新权限默认拒绝，逐项加入。
3. 任意第三方前端代码不得作为同源脚本注入主站；简单扩展由宿主声明式渲染。确需执行前端插件时，先落地隔离来源 / iframe 消息协议，再开放入口。
4. 后台任务的持久化不自动等于外部操作可安全重试。网络写入要有动作特定的幂等或核对办法；不能因为 lease 过期就重复执行未知副作用。
5. WebAssembly 第一阶段不等于完整 OS 沙箱。开放不受信任发布者前，补独立 worker 资源 / 故障隔离、发布者认证和撤销链，再做市场规模扩展。
6. 用户明确不要求旧数据、旧 API 或旧插件 ABI 兼容；这不免除新 SDK 发布后的版本责任。破坏性变化须有版本声明、升级阻止策略和真实插件消费者验收。

网络限制与 Windows 接手步骤继续以 `local-network-handoff.md` 为准。插件 / Bridge 开发缺口不归咎于网络。
