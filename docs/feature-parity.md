# 原版功能对照与 80% 目标

本清单保留原项目功能覆盖口径；当前开发顺序和版本范围以 [新更新路线](refactor-next-steps.md) 为准。旧路线的发布门禁不由本表继承。

基线：原项目 `94f64e7`。以 README、实际前端页面、后端路由及部署工具为依据，冻结 62 项可独立验收的功能。详细条目和证据保存在 `feature-parity.json`。至少 **50 / 62** 项完成才满足本清单的 80% 目标。

统计的是功能覆盖广度，不代表相同开发工作量或生产就绪程度。只有后端、适用的用户入口及验收均完成才记 1 项；部分完成、仅接口、仅模拟上游验证、受环境阻塞均记 0。不得通过删除缺口或拆分已完成项提高比例。与旧版可以有实现方式差异，但必须保留对应用户流程和权限边界。

截至 2026-10-07，本地接手后已验收 **52 / 62 项（83.9%）**，达到本清单至少 50 项的目标。本轮开始时为 10 / 62 项（16.1%）。计数明细、测试入口和报告路径见 `feature-parity.json`。

完成部分包括账号与两步验证、个人手账及历史管理、批量操作、标签 / 预设、统计 / 偏好、导入与含图备份、公开手账 / 目录 / 分享、专栏及审核、管理 / 审计 / 健康维护、独立实例安装 / 迁移 / 更新回滚、API 合同。

F50 的已验收范围为站点名、简介、注册开关，以及通过实例 CLI 管理来源、端口、数据库、镜像和持久实例密钥；外部服务配置已补齐；对应服务在真实凭据验收前保持未完成，不由本项代表可用。

## 历史覆盖顺序

以下四步记录达到原版 80% 目标时的实施顺序，后续不以它重新排序新路线。

1. 数据与账号基础：完整番剧资料、历史编辑、批量管理、偏好和账号安全。
2. 导入与备份：新项目 JSON、CSV、预览、原子提交、重复与恢复。
3. 分享与管理：公开权限、个人手账、专栏、首次管理初始化、审核和审计。
4. 资料源、后台任务、实例维护及集成；按实际可验证程度更新覆盖。

## 当前环境限制

主开发环境为 Linux + Docker，真实 PostgreSQL、race、容器实例运维和浏览器验收已有记录。本地 Windows 曾完成 Bangumi 公共 API 和原生 PostgreSQL 验收，当时 Docker Desktop Linux engine 未就绪，不代表当前云端缺少 Docker。当前仍缺邮件、OAuth、R2 的正式业务凭据/联调证据；网络受限仅阻塞对应真实服务检查，见 [本地交接](local-network-handoff.md)。

所有实际限制、已完成项、未完成项和验证证据会持续更新；原项目的插件、Bridge、安装与更新功能均保留在分母中。
