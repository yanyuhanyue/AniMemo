# AniMemo v1.1 Technical Backlog

来源：`docs/full-repository-audit-20260811.md`

本 backlog 只承接全仓审计中的 P2/P3。它不是 v1.0 release blocker 清单，也不授权在单个 PR 中同时启动 Architecture Contract Hardening、Mobile、Plugin Runtime v3 与 UIUX 2.0。

## Working Rules

- 每项先写 contract/acceptance tests，再做 scoped implementation。
- Dashboard V1.0 Core 在明确解冻前不得因可维护性项重写。
- Backend/Frontend plugin 当前 trust model 不得在没有产品安全决策时偷偷改变。
- 不进行 destructive migration；公共 API 改动必须有兼容/迁移策略。
- 每个主题使用独立 PR，中文 commit 与 PR 标题，全部 required gates 后 Squash Merge。

## Security Hardening

### V11-SEC-001 Frontend container defense-in-depth

- Source findings: AUD-P3-002
- Scope: nginx non-root feasibility, read-only root filesystem, tmpfs, capability drop, explicit security options.
- Acceptance: production-like Docker Gate and static/media serving pass; no host/global Docker changes.

### V11-SEC-002 Frontend plugin trust/isolation decision

- Source findings: AUD-P2-007
- Scope: document trusted publisher rules and compare same-origin, iframe and isolated-origin options.
- Acceptance: explicit product/security ADR; do not implement a partial sandbox that still exposes ambient authority.

### V11-SEC-003 Backend plugin trust/isolation decision

- Source findings: AUD-P2-008
- Scope: preserve trusted-superuser model for v1 while defining worker/RPC/container target properties.
- Acceptance: ADR covers installation/publish authority, filesystem, network, secrets, resource limits and failure containment.

## Architecture

### V11-ARCH-001 Version the Core API

- Source findings: AUD-P2-001
- Scope: define `/api/v1` compatibility, deprecation and routing policy.
- Acceptance: existing web client migrates without a flag day; stateful upgrade and OpenAPI gates cover both transition and final state.

### V11-ARCH-002 Separate Auth Core from Web transport

- Source findings: AUD-P2-002
- Scope: token/session semantics independent from cookie/CSRF delivery.
- Acceptance: web retains HttpOnly cookie security; a native adapter can use secure storage without weakening web CSRF.

### V11-ARCH-003 Separate API transport from browser UI

- Source findings: AUD-P2-003
- Scope: inject base URL, credentials, navigation and browser services around reusable domain/API modules.
- Acceptance: transport/domain unit tests run without `window`/`document`; browser adapter behavior remains unchanged.

### V11-ARCH-004 Define stable resource identities

- Source findings: AUD-P2-001, AUD-P2-006
- Scope: document public/internal IDs, mutation idempotency keys and cross-client URL stability.
- Acceptance: OpenAPI and client contracts stop relying on deployment-specific assumptions.

### V11-ARCH-005 Reduce Dashboard orchestration concentration

- Source findings: AUD-P2-004
- Scope: only after explicit Dashboard unfreeze, split by real domain ownership and behavior tests.
- Acceptance: no UI redesign; existing query/mutation/pagination E2E remains unchanged.

## Performance

### V11-PERF-001 Replace synchronous Integration idle polling

- Source findings: AUD-P2-011
- Scope: evaluate ASGI notification, Redis pub/sub/wakeup, database notification or bounded short-poll options.
- Acceptance: preserve Protocol v1 cursor/ACK/replay semantics; measure worker and DB query reduction under concurrent idle clients.

### V11-PERF-002 Paginate plugin list surfaces

- Source findings: AUD-P2-013
- Scope: marketplace, installed plugins and developer project/version lists.
- Acceptance: stable ordering, bounded response sizes, query-count tests and backward-compatible frontend migration.

## Testing

### V11-TEST-001 Add three low-maintenance critical browser journeys

- Source findings: AUD-P2-014
- Candidate journeys: Watch History add/edit, staff authorization boundary, plugin marketplace read/install visibility.
- Acceptance: production build, self-contained fixtures, deterministic cleanup, no external network dependency.

### V11-TEST-002 Convert behavior-critical source assertions

- Source findings: AUD-P2-015
- Scope: inventory `readFileSync`/regex tests; retain valid static contract tests and replace only behavior claims.
- Acceptance: each conversion asserts an observable runtime result and does not reduce package/security contract coverage.

### V11-TEST-003 Expand high-confidence static rules

- Source findings: AUD-P2-016
- Scope: trial `react-hooks/exhaustive-deps` and 1-2 additional Ruff correctness families in isolated reports.
- Acceptance: low false-positive rate, scoped fixes, no repository-wide style rewrite.

## Plugin Platform

### V11-PLUGIN-001 Complete Plugin SDK operational contracts

- Source findings: AUD-P2-009
- Scope: storage, transactions, time, external network and structured errors as explicit Host capabilities.
- Acceptance: official importer no longer needs direct Django/plugin_host operational imports for supported functions.

### V11-PLUGIN-002 Make runtime registrations portable

- Source findings: AUD-P2-010
- Scope: declarative hook/action/event descriptors and lifecycle/reconciliation contract.
- Acceptance: registrations can be represented across worker/RPC boundaries without callback identity assumptions.

### V11-PLUGIN-003 Define OpenAPI extension for plugin routes

- Source findings: AUD-P2-006
- Scope: per-plugin schema artifact, namespace, version and error-code publication.
- Acceptance: enabled plugin API contracts are discoverable without weakening dynamic runtime validation.

### V11-PLUGIN-004 Trusted publisher roadmap

- Inputs: audit future-platform requirements.
- Record only: Trusted Publisher, Trusted Runtime Publisher, exact Git commit, SHA-256/package CAS, review provenance, revocation and rollback semantics.
- Acceptance: design document; no marketplace/registry implementation bundled into Runtime v3 work.

## Mobile Readiness

### V11-MOBILE-001 Native auth assumptions

- Source findings: AUD-P2-002, AUD-P2-003
- Scope: SecureStore-style refresh storage, token rotation, device logout/revocation, CSRF separation.
- Acceptance: threat model and API contract only; do not create an Expo/React Native app in this item.

### V11-MOBILE-002 Shared API/error core

- Source findings: AUD-P2-001, AUD-P2-006
- Scope: stable DTOs, error codes, retry metadata and resource identities.
- Acceptance: generated or handwritten shared client can be tested independently from DOM/browser APIs.

## UIUX / Theme

### V11-UI-001 Theme Contract

- Source findings: AUD-P2-005
- Scope: primitive -> semantic -> component tokens; typography, color, spacing, shadow, motion and focus states.
- Acceptance: contract/ADR and a small non-Dashboard pilot; no whole-app redesign in the first PR.

### V11-UI-002 Plugin semantic slots

- Source findings: AUD-P2-005, AUD-P2-007
- Scope: define safe extension slots rather than unrestricted DOM coupling where practical.
- Acceptance: current official plugin remains functional and future theme changes do not require plugin-specific CSS guessing.

## Operations

### V11-OPS-001 Bound AstrBot pending state

- Source findings: AUD-P2-012
- Scope: maximum pending size, age/expiry, dead-letter diagnostics and operator recovery.
- Acceptance: no silent notification loss; cursor/ACK tests cover overflow and route restoration.

### V11-OPS-002 Upgrade GitHub Actions majors

- Source findings: AUD-P3-001
- Scope: Dependabot action upgrades.
- Acceptance: PR and main push CI/Release Gate pass; stateful base resolution remains correct.

### V11-OPS-003 Remove environment-specific defaults from reusable surfaces

- Source findings: AUD-P3-003
- Scope: bridge/example defaults and deploy topology parameters.
- Acceptance: current production remains the documented example, while alternate environments fail clearly rather than inheriting the wrong host/container.

### V11-OPS-004 Application version policy

- Source findings: AUD-P3-004
- Scope: decide whether root package version follows AniMemo release tags, stays private metadata or is generated.
- Acceptance: one authoritative release identity documented across Git, artifacts and runtime diagnostics.

### V11-OPS-005 Legacy browser-token cleanup cutoff

- Source findings: AUD-P3-005
- Scope: choose a compatibility date/release after which local/session token scrubbing can be removed.
- Acceptance: security documentation confirms no supported build stores refresh/access tokens in browser storage.
